# Reference: AOSP `boot_signer` (test oracle only)

Nothing here is linked into `abr` or needed to build or use it. These files
let `tests/run_tests.sh` check abr's AVBv1 boot signature (the pre-AVB-2.0
signature appended after a boot image) against the **real** tool.

| File | What it is | Source |
|---|---|---|
| `BootSignature.java`, `Utils.java` | AOSP `system/extras/verity` -- the `boot_signer` command (`java ... com.android.verity.BootSignature /boot image.img key.pk8 cert.pem out.img`, and `-verify`) | `LineageOS/android_system_extras`, branch `lineage-19.1`, commit `51de782c54aebc8817d78956a832eefab1a330d1` (a mirror of AOSP) |
| `LICENSE` | the `NOTICE` that accompanies those sources (Apache License 2.0) | same |
| `verity.pk8`, `verity.x509.pem` | AOSP's public "verity" dev key pair, `build/target/product/security/` (present up to `android-8.1.0_r1`) | `aosp-mirror/platform_build` |

The key pair is the one Android Image Kitchen signs with by default. It is
**public** (the private half has been in the AOSP tree since 2014) and is not
a secret; it must never be used for anything that has to stay trustworthy.
abr embeds the same pair (`src/legacy/avb1_aosp_key.cpp`, generated by
`tools/gen_aosp_verity_key.py`); the test suite regenerates that file from
these two and compares, so the embedded copy cannot drift.

sha256: `verity.pk8` 75b25533...4145, `verity.x509.pem` (as DER)
8ad127ab...3b86.

## How the tests use it

`tests/run_tests.sh` compiles the two Java files with `javac` against
BouncyCastle (`bcprov.jar`; Debian/Ubuntu: `apt install default-jdk-headless
libbcprov-java`) into a temporary directory, and skips the checks that need
it when either is missing. The comparison that matters: signing the same
image with the same key must give the **same DER bytes** from the real tool
and from abr (PKCS#1 v1.5 is deterministic). That was also checked once
against a real device image: re-signing the unsigned part of a vendor's
`boot.img` with this tool and key reproduced the signature stored in it, byte
for byte.

`tests/tools/avb1.py` is a second, independent implementation (DER assembled
in Python, RSA from the `openssl` command) that does not need Java.

Boot images signed with this scheme are limited to header versions 0-2 by
the real tool (`getSignableImageSize` rejects v3/v4), which matches reality:
v3+ images are covered by AVB 2.0.
